## 한 줄 요약

학생이 태블릿으로 푼 **풀이 과정·소요 시간·수정 이력**을 AI로 분석해서
교사에게 **"어디서 막혔는지 + 취약 개념 + 보충 지도 방향"**을 근거와 함께 보여준다.

## 핵심 학습 흐름 (서비스 방향)

학생이 **문제를 계속 풀수록** 개인별 장점·단점이 쌓이고, 그 단점 위주로 다음 학습을 이어 가 실력을 올린다.

```
문제 풀이 ─▶ 풀이 분석 ─▶ 개인별 장점·단점 파악 ─▶ 단점 위주 문제 배정 ─▶ 다시 풀이 ─▶ 변화 확인
   ▲                        (개념·오류 유형별 누적)    (DB 문제 + 장단점 매칭)                │
   └───────────────────────────────────────────────────────────────────────────────┘
```

- 한 번의 풀이로 판단하지 않고, 풀이가 **쌓일수록** 장점(잘하는 개념)과 단점(반복 오류·취약 개념)을 더 정확히 본다
- **DB에 저장된 문제**(개념·오류 유형 정보)와 **학생 개인의 장단점**을 맞춰서 단점을 보완할 문제를 고른다
- 잘하는 부분은 줄이고 **단점 위주로** 학습하게 해서 학습 효율을 올린다
- 다시 푼 결과로 단점이 줄었는지 확인하고, 그 결과가 다음 문제 선택에 반영된다 (학년이 바뀌어도 기록이 이어짐)

## AI 파이프라인

```
[학생 태블릿 필기]  ──▶ ① 문제지 구조화        업스테이지 Document Parse
                       ② 손글씨 인식          업스테이지 Document OCR
                       ③ 풀이 단계 분석        LG AI연구원 EXAONE 4.5 (원본 이미지 + OCR 결과 + 정답·해설)
                       ④ 학습 기록 종합·지도 제안  업스테이지 Solar Pro 4 (+ 풀이 시간·정오답·수정 이력)
                    ──▶ [교사 대시보드]
```

**지금 구현 (2026-11-19)**: EXAONE 4.5(이미지 입력)는 무료 호스팅 API 가 없고 33B 라 16GB 맥에서 못 돌려 보류.
손글씨는 **업스테이지 OCR** 로 읽고, 확신 없는 줄이 있으면 **Mathpix → Claude** 순서로 다시 읽는다.
Claude 는 **못 읽은 줄 다시 읽기에만** 쓴다(`claude -p`, API 키 없이 구독). OCR 보정·채점·학생 요약은 원본처럼 **Solar Pro 4**.
약분 빗금·줄을 그어 지운 흔적은 획에서 찾아 OCR 이미지에서 빼고 채점 AI 에게 알려 준다 (재현 프롬프트 v4 기준).

```
필기 획 ─▶ OCR 전용 이미지 ─▶ 업스테이지 OCR ─┬─(확신 없는 줄이 있으면)─▶ Mathpix ─(그래도 이상하면)─▶ Claude: 이미지 전체를 다시 읽음 ─┐
                                           └───────────────────────────────────────────────────────────────────────────┴─▶ Solar 보정 ─▶ Solar 채점 ─▶ Solar 학생 요약 ─▶ 교사 대시보드
                                                                                                                          (미지수에 맞춰)  (+코드 검산·빗금 표시) (+코드 집계·근거 확인)
```

- Mathpix 키(`MATHPIX_APP_ID`·`MATHPIX_APP_KEY`)가 없으면 Mathpix 는 건너뛰고 바로 Claude
- Claude 는 서버가 `claude` CLI 를 직접 실행하는 방식이라 **`claude` 로그인된 노트북에서 서버를 띄워야** 함 (Vercel 배포에서는 Claude 단계가 안 됨)
- 한 건당 다시 읽기 ~5초, 분석 ~6~11초 (sonnet 기준)

- 오류 유형: 교사 설문 8개(조건 놓침, 구하는 값 혼동, 음수 부호, 괄호 일부만 곱함, 괄호 앞 음수 부호, 대입 괄호, 이항 부호, 덧셈·뺄셈 계산) + 동류항·계수 나누기 등
- 학생 요약은 약점마다 **실제 풀이의 틀린 줄을 근거로** 보여 주고, OCR 이 이상하게 읽은 풀이는 `✎ 글씨체 문제`로 따로 표시
- 검사: `npm run test:weakness` 88/88·20/20, `npm run test:ocr` 줄 정확도 **86%** (OCR 만 62%, 처음 15%) — 자세한 내용은 [개발계획](개발계획.md#911-ai-채점약점-분석-pr-13--15)

확장 단계(시연 범위 밖): NC AI VARCO-VISION 재검토, KT 믿:음 수준별 설명, SKT A.X 학습 기록 질의, VARCO Voice 음성 설명

## 실행 방법

DB는 **Supabase**(클라우드 PostgreSQL) 프로젝트 **하나를 팀 전체가 같이** 씁니다. 설치할 것은 Node.js 뿐이에요.

> 팀 프로젝트는 **이미 만들어져 있어요** (서울 리전, 테이블·시연 데이터 들어 있음).
> 팀원은 프로젝트를 새로 만들지 말고, 접속 주소만 받아서 아래 **2번**부터 하면 됩니다.

### 1. Supabase 프로젝트 만들기 (팀에서 한 명만, 이미 완료)

다시 만들어야 할 때만 참고하세요.

1. https://supabase.com 가입 → 조직(Organization) 만들 때 Plan은 **Free**
2. **New project**
   - Database Password: **영문·숫자로만** 정하고 따로 보관 (특수문자 `@ # / ?` 는 접속 주소를 깨뜨림)
   - Region: **Auto 말고 Asia-Pacific → Seoul** (Auto로 두면 인도 뭄바이로 잡혀 DB가 10배 느려짐)
3. 프로젝트 상단 **Connect** → **Session pooler** 주소 복사. 주소에 `ap-northeast-2` 가 있으면 서울
   (`postgresql://postgres.<프로젝트ID>:[YOUR-PASSWORD]@aws-0-ap-northeast-2.pooler.supabase.com:5432/postgres`)
   - Direct connection 주소는 와이파이에 따라 접속이 안 될 수 있어 쓰지 않음
4. 아래 2번까지 하고 `npm run db:setup` 한 번 → 테이블·시연 명단·기본 과제 생성

### 접속 주소·대시보드 공유

- 접속 주소는 팀원에게 **개인 메시지로** 전달 (비밀번호가 들어 있으니 단톡·깃허브·채팅 AI에 올리지 말 것)
- 팀원도 Supabase 대시보드를 보려면: 조직 설정 → **Team** → 이메일로 초대
- 무료 플랜 제한
  - 한 조직에서 켜 둘 수 있는 **프로젝트(DB)가 2개**. 접속하는 사람·컴퓨터 수 제한은 아님
  - DB 용량 500MB (풀이 이미지 포함해도 시연 규모는 충분)
  - **1주일 동안 안 쓰면 일시정지** → 대시보드에서 Restore

### 2. 내 컴퓨터 세팅 + DB 연결 (팀원 각자, 처음 한 번)

준비물: Node.js, 팀장에게 **개인 메시지로 받은** 업스테이지 키와 DB 접속 주소(`DATABASE_URL`)

**① `.env` 만들기** (저장소 루트에서)

```bash
cp .env.example .env
```

**② `.env` 에 두 줄 채우기** (나머지 줄은 그대로 둬도 됨)

```bash
UPSTAGE_API_KEY=up_xxxxxxxx
DATABASE_URL=postgresql://postgres.<프로젝트ID>:<비밀번호>@aws-0-ap-northeast-2.pooler.supabase.com:5432/postgres
```

- 받은 주소를 **통째로** 붙여 넣기. 주소에 `[YOUR-PASSWORD]` 가 남아 있으면 그 자리에 비밀번호를 넣고 **대괄호도 지우기**
- 주소에 `pooler.supabase.com` 과 `ap-northeast-2` 가 들어 있어야 함 (Direct connection 주소 `db.<ID>.supabase.co` 는 쓰지 않음)
- `=` 앞뒤에 띄어쓰기·따옴표 넣지 않기
- (선택) `MATHPIX_APP_ID=`·`MATHPIX_APP_KEY=` 를 채우면 OCR 이 못 읽은 풀이를 Mathpix 가 먼저 다시 읽음. 비워 두면 바로 Claude 가 읽음
- **Claude**: 터미널에서 `claude` 가 로그인돼 있어야 함 (API 키 필요 없음). PATH 에 없으면 `CLAUDE_CLI=` 에 전체 경로. 모델은 `VISION_MODEL` (기본 sonnet)

**③ 설치하고 연결 확인**

```bash
cd app
npm install
npm run db:setup
```

이런 줄이 나오면 연결 성공이에요. 팀 DB에는 이미 데이터가 있어서 **여러 번 실행해도 안전**합니다 (지우거나 덮어쓰지 않음).

```
✓ 01_schema.sql
✓ 02_seed.sql
✓ 03_learning.sql
✓ 04_security.sql
· 과제가 이미 있어 기본 과제는 건너뜀
학생 N명 · 과제 N개 · 풀이 N건
```

`✗` 로 시작하는 줄이 나오면 아래 **자주 나는 문제** 참고.

### 3. 매번 개발할 때

```bash
cd app
npm run dev              # http://localhost:3000
```

- 데모 계정: 선생님 `teacher` / `1234`, 학생은 반·번호 선택 + `0000`. `npm run db:demo` 로 시연 데이터를 넣었다면 `teacher2`(2학년 1반)도, `teacher` 에 AI 요약 확인용 1학년 5반도
- **`git pull` 하거나 브랜치를 바꾼 뒤에는** `npm install` → `npm run db:setup` 순서로 한 번 (패키지·테이블이 추가됐을 수 있음, 기존 데이터는 그대로)
- 개발 서버(`npm run dev`)는 **한 개만** 켜기. 같은 폴더에서 두 개 켜거나, 켜 둔 채로 `npm run build` 하면 `.next` 폴더가 꼬여요
- 같은 와이파이의 태블릿에서 열려면 `http://<내 컴퓨터 IP>:3000`
- **DB를 같이 쓰기 때문에** 내가 낸 과제·풀이가 팀원 화면에도 바로 보여요. 테스트 데이터는 지울 때 단톡에 먼저 말하기

### DB 보기

- Supabase 대시보드 → **Table Editor**: 표로 보기·수정
- Supabase 대시보드 → **SQL Editor**: `SELECT * FROM students;` 같은 SQL 실행
- 테이블 설명은 [app/README.md](app/README.md#데이터베이스-supabase--필수) 참고

**자주 나는 문제**
- 화면에 "DB에 연결할 수 없어요" → 인터넷 연결, `.env` 의 `DATABASE_URL` 확인, 대시보드에서 프로젝트가 일시정지(Paused)됐으면 **Restore**
- "DB 비밀번호가 틀렸어요" → `[YOUR-PASSWORD]` 자리에 실제 비밀번호를 넣었는지 (대괄호도 빼야 함). 비밀번호를 잊었으면 Project Settings → Database → Reset database password 후 팀원 모두 `.env` 수정
- 화면이 느리면 → 접속 주소에 `ap-northeast-2`(서울)가 들어 있는지 확인
- `.env` 를 고친 뒤에는 `npm run dev` 를 껐다 켜야 반영됨
- `column ... does not exist` / `relation ... does not exist` → 새 브랜치의 테이블이 아직 없음. `cd app && npm run db:setup`
- `Cannot find module './611.js'` 같은 오류 → `.next` 가 꼬임. 개발 서버를 모두 끄고 `cd app && rm -rf .next && npm run dev`
- 소그룹이 안 보이면 → 같은 실수를 한 학생이 2명 이상이어야 생겨요. 테스트용 데이터는 `npm run db:demo`

| 브랜치 | 용도 | 예시 |
|---|---|---|
| `main` | 시연 가능한 최신 버전. **직접 커밋·푸시 금지** | |
| `feat/작업이름` | 새 기능 | `feat/db-students`, `feat/supplement` |
| `fix/작업이름` | 버그 수정 | `fix/login-redirect` |
| `docs/작업이름` | 문서·발표 자료 | `docs/pitch-deck` |
| `chore/작업이름` | 설정·패키지 등 | `chore/eslint` |

- 브랜치 이름은 **영어 소문자 + 하이픈**, 한 브랜치에는 한 가지 작업만
- 커밋 메시지는 **한국어 한 줄**로 무엇을 했는지 (필요하면 아래에 자세히)
- 브랜치는 오래 두지 말고 작업이 끝나면 바로 합치고, 합친 뒤에는 삭제
- 합치기 전 `cd app && npm run build` 가 통과해야 함
- **해커톤 전날부터는 `main`에 버그 수정만** 합칩니다

### 작업 순서

```bash
# 1. 최신 main 에서 브랜치 만들기
git switch main
git pull
git switch -c feat/작업이름

# 2. 작업하면서 커밋
git add .
git commit -m "학생 정보를 DB에서 읽도록 변경"

# 3. 올리고 GitHub에서 PR 만들기 (base: main)
git push -u origin feat/작업이름

# 4. PR 링크를 단톡에 공유 → 팀원 1명 확인 → Merge → 브랜치 삭제
# 5. 다른 사람이 main 을 바꿨으면 내 브랜치에 반영
git switch feat/작업이름
git pull origin main
```
